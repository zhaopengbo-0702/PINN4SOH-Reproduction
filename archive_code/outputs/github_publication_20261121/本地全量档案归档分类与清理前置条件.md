## 可重下载依赖与第三方数据

`legacy_runtime/legacy_asset_manifest.json`、`legacy_torch_manifest.json`保存官方依赖的URL和SHA；`reproduction/offline-wheels-manifest.json`保留现代依赖来源。仅将`.whl`、明确的conda包和其压缩包装归依赖；脚本、补丁、安装探针、日志与manifest均是本实验记录。

MIT镜像三份H5合2,202,644,831字节，来自记录在`feature_audit/MIT_mirror_audit/zenodo_record.json`的第三方派生数据，不能称原MAT。附LICENSE和来源SHA，不把这三份H5与我们计算出的全行映射、残差和签名混为一类。原始XJTU/HUST/TJU ZIP总约5.3GB，同样需保留数据来源与许可。第三方原始数据是否公开分发由root核对，不因本文件计划而自动发布。

## 已通过SHA确认的大文件重复

大于20MiB且大小相同的文件已逐SHA核对，发现5组精确重复；每组保留一份可减少2,637,323,013字节。完整路径与SHA在`LOCAL_LARGE_EXACT_DUPLICATES.json`。这只是已核定重复下界，小文件和打包/解包等价尚未全量去重。

- 1.338GB旧离线ZIP的独立副本与reassembly副本完全一致。
- 1.157GB Torch wheel、53.76MB Python conda包、38.12MB SciPy wheel在runtime和payload/assets中逐字节一致。
- 两份50.37MB `per_battery.csv`完全一致，分别位于full_evidence和full_report目录。

上传分片与完整ZIP不是逐字节相同文件；须依据原分片清单拼接并验证完整SHA，才能认定包装可恢复。`within_cycle_index.csv.part`和`index_first8mb.bin`是中间下载片段，不能仅由名字判等；核完整索引与来源后才能丢弃它们。

## 安全清理的必要门槛

最终远端归档清单须覆盖本实验的所有独有文件，包括成功、不利、失败、历史版本及原数据来源记录。每个远端资产校验大小与SHA，至少实际下载回读一次；包内成员清单也要复核。仅GitHub上显示文件名、asset API存在或云盘双目录副本不足以证明已经可独立恢复。

清理清单只能列当前账号下本实验的绝对路径及预期SHA，不能在共享父目录、其他用户目录、全局缓存或任意computed root上递归删除。若仍有独有文件未取回/未上传，应留原件并明确未清理。本文件没有授权或执行任何删除，也未把当前四训练包称作整个19.59GB工作区的完整备份。
