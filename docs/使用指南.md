## 下载模型和完整实验日志

打开[发布下载页](https://github.com/zhaopengbo-0702/PINN4SOH-Reproduction/releases/tag/v1.0.0)，下载对应 `.tar.gz` 及 `SHA256SUMS.txt`。单个包的内容、是否包含模型、数组和配置见[文件与下载说明](文件与下载说明.md)。

```powershell
Get-FileHash .\pinn4soh-main-2120.tar.gz -Algorithm SHA256
tar -xzf .\pinn4soh-main-2120.tar.gz
```

Linux/macOS 可用 `sha256sum -c SHA256SUMS.txt` 核对已下载文件。归档内另有逐文件 SHA 清单。Windows 某些历史路径较长，建议在短路径（例如 `D:\PINN4SOH`）解压，并启用支持长路径的工具。

## 从代码运行一个短验证

作者源码参考版本为 `cc3cc5053caf38f04e0665f7f88cb109144d035e`。仓库中的 `PINN4SOH/` 是实验时保存的源码快照；较大的发布特征与权重由下载包或作者来源提供。不要无条件用今天上游的最新提交覆盖历史源码。

示例：

```bash
git clone https://github.com/zhaopengbo-0702/PINN4SOH-Reproduction.git
cd PINN4SOH-Reproduction

# 作者原仓库中的 data/ 放在 PINN4SOH/data/ 下，保留其使用条件
# 先检查当前 CUDA 版 PyTorch，不要把已配置的 GPU 版本覆盖成 CPU 版
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
python -m pip install -r reproduction/requirements-cloud.txt

python reproduction/run_reproduction.py \
  --repo PINN4SOH --output runs/smoke \
  --dataset XJTU --smoke --threads 2
```

`--smoke` 仅验证短训练流程，不是论文精度。运行器默认要求 CUDA；明确只做 CPU 小验证时可加 `--allow-cpu`。输出用新目录，避免覆盖已有证据。

本项目主现代环境为 Python 3.10.13 / PyTorch 1.13.1+cu116 / NumPy 1.24.4；另有 Python 3.7.10 / PyTorch 1.7.1 旧栈对照。当前脚本包含现代 Python 语法，旧栈应使用保存的兼容流程，不应只换解释器后直接运行所有新工具。

## 重跑当前默认参数批次

```bash
python reproduction/run_reproduction.py \
  --repo PINN4SOH --output runs/current-defaults \
  --dataset all --repeats 10 --epochs 200 --threads 2 --resume
```

这会运行 XJTU 六批、TJU 三批、MIT/HUST 各一批，每批十次，共 110 次，属于作者修正版默认参数实验。它不包含主 2120 中的所有基线、小样本和迁移。

## 主 2120 的计划与调度

先按实际路径生成计划，并查看 dry-run：

```bash
python reproduction/make_paper_plan.py \
  --output runs/plans \
  --reference /workspace/pinn4soh_main_20261109 \
  --source-suite /workspace/pinn4soh_full_paper_stage1

python reproduction/run_full_suite.py \
  --plan runs/plans/stage1_plan.json --repo PINN4SOH \
  --output runs/stage1 --gpus 0 --workers-per-gpu 1 --threads 2 --dry-run
```

计划中的参考 split 和源权重路径必须确实存在，不能机械复制示例。正式运行需去掉 `--dry-run`，先运行 smoke，并在 stage1 源任务全部完成后再运行 stage2。下载包内包含已执行计划、配置和历史脚本，主实验绑定版本见其 manifest。

共享服务器建议单卡、单 worker，遵守实验室资源规定。运行批次和重跑论文全部矩阵不同，开始前先测一个有代表性的训练耗时。
