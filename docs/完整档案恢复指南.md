# 完整档案恢复指南

本页说明如何核验和恢复已整理的文件。**附件是否已经全部上传，以发布页及最终远端核验记录为准**；文件备份完成也不代表原论文所有数值和结论一致。

## 需要下载什么

从[完整档案发布页](https://github.com/zhaopengbo-0702/PINN4SOH-Reproduction/releases/tag/archive-20261121)下载两组材料，保持每组文件放在各自目录：

| 目录示例 | 必要材料 | 用途 |
|---|---|---|
| `local/` | 24 个 `full-cas-part-*.zip`、`index.json`、`restore_full_archive.py` | 本地已有实验与数据的完整内容去重档案 |
| `cloud/` | 9 个 `cloud-needed-part-*.zip`、`CLOUD_INVENTORY.json`、`NEEDED_ARCHIVE.json`、`FILESYSTEM_METADATA.json` | 本次补齐的云端独有内容及文件系统元信息 |
| `cloud/` | `discarded-code-only.zip`、`DISCARDED_CODE_ONLY.json` | 仅保留舍弃分支的源码和配置，不包含该批训练结果 |
| `cloud/` | `SCAN_ADJUDICATION.json`、`SCAN_PUBLIC_REFERENCE_COMPARISON.json` | 14 项扫描误报与公开软件分发包逐字节一致的独立审定 |
| 任意工具目录 | `cloud_delta_local.py` | 联合校验与普通文件安全恢复工具 |

原云中转曾产生 18 个体积较大的初始包；与本地档案按 SHA 去重后，最终只需要上述 9 个云新增包。云包依赖本地档案，单独下载云包不能恢复所有云文件。

本地独立联合核验已经逐文件重组通过：**62,582 份保留的云普通文件，共 12,733,411,140 字节**。每个文件的完整 SHA 与原云清点索引一致，并核对 68,782 条文件系统元信息、1,207 个符号链接目标及 112 份代码补包成员。原始文件未改写。

`CLOUD_ALL_RETAINED_COVERAGE_VERIFIED.json` 记录本地实际验证；其 SHA-256 为：

文件数量与字节数是档案范围，不是训练次数。用户舍弃的未完成追加实验结果与 Python 缓存不属于保留成果；原主实验的不利结果仍保留。

## 下载后自行核验

仅需要 Python 标准库。先检查本地完整档案：

```bash
python restore_full_archive.py --index local/index.json --archives-dir local --verify-only
```

再联合核对所有保留云文件；下面的命令只读文件，不展开原数据：

```bash
python cloud_delta_local.py verify \
  --cloud-index cloud/CLOUD_INVENTORY.json \
  --local-index local/index.json \
  --local-parts local \
  --needed-index cloud/NEEDED_ARCHIVE.json \
  --needed-parts cloud \
  --scan-adjudication cloud/SCAN_ADJUDICATION.json \
  --scan-references cloud/SCAN_PUBLIC_REFERENCE_COMPARISON.json \
  --receipt MY_CLOUD_COVERAGE_VERIFIED.json
```

工具先校验每个读取归档的整包 SHA，再校验内容块和完整文件重组 SHA；同时检查路径、元信息、代码补包和扫描审定的绑定。它拒绝不同内容的覆盖、路径越界、缺包、坏包或不完整扫描审定。

## 恢复文件

本地完整档案可按原相对目录结构恢复到全新目录：

```bash
python restore_full_archive.py --index local/index.json --archives-dir local --output restored-local
```

对云文件，在联合核验命令中添加 `--output restored-cloud` 即可恢复普通文件。目标目录必须不存在。

**云环境目录应在 Linux 文件系统中展开。** `legacy37/share/terminfo` 内存在 Linux 大小写不同名文件，普通 Windows 目录会冲突。Windows 可以运行只读联合校验，但安全恢复工具会拒绝在其普通目录中展开完整云文件树。

工具不会创建、跟随符号链接或自动设置执行权限；恢复时将元信息保存为 `.CLOUD_FILESYSTEM_METADATA.json`。若需要重建可运行 Linux 环境，应在隔离目录中逐项应用目录、权限和链接元信息，并核对每条链接解析后仍在恢复根内。文件已保存不表示迁移后的 Python、CUDA 或 GPU 前向已验证可运行。

## 扫描结果为什么仍写 held

原云新增文本扫描保留 14 项 `held_sensitive_text_match` 命中。随后从实际下载包重组文件，与官方 Python 3.7.10 安装包及 PyPI `future` 公共源码分发包逐字节对照，14 项全部一致：标准库字面串与公开 SSL 测试密钥样例。

原扫描结果没有被改成通过；`SCAN_ADJUDICATION.json` 另存独立审定。联合核验只有在所有命中均有完整、SHA 绑定的审定时才接受原 held 状态。审定不展示命中值，也不构成未扫描范围的保密保证。
