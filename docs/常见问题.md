# 常见问题

## 这个仓库提供了什么？

提供 PINN4SOH 论文复现的中文说明、实验代码、汇总图表、关键 CSV、复核报告和证据索引。适合先在线了解做了什么、结果如何、有哪些未复现项，再按需下载较大的训练证据。仓库首页和发布附件的内容范围以各自索引为准。

## 整篇论文已经 100% 复现了吗？

**主训练矩阵 2120/2120 已完成，但全部数值和结论没有与原文完全一致。** 常规估计、小样本、目标域独训补充和迁移都已覆盖；MIT/HUST 的部分均值优势、小样本普遍最好、普遍迁移优势等仍存在反例，另有原材料无法唯一恢复的细节。见[实验结果](实验结果.md)和[未复现与限制](未复现与限制.md)。

## 2120、20、110、192 分别是什么？

| 数字 | 含义 |
|---|---|
| 2120 | 本项目主实验矩阵，常规 440＋小样本 1120＋目标域独训补充 80＋迁移 480。 |
| 默认参数 20 | 原有默认参数常规运行中，MIT/HUST 各 10 次的独立复核，使用作者修正版默认设置。 |
| CPU 复载 20 | 对上述 20 个已保存模型重新推理，不是 20 次新训练。 |
| 旧栈 110 | 99 次新增旧栈训练加 11 次原有 repeat1 复用，形成 110 配对。 |
| 192 | XJTU/2C 另行设计的 64 配置×3 seed 替代搜索，随后做了 3 次选后测试。 |

这些批次用途和配置不同，不能简单合并为一套重复次数。未完成的额外调参已按用户要求撤出交付，不支持改进结论。

## 为什么同一个数据集会出现两种 MAPE？

“合并全部样本”让样本较多的 CSV 权重更大；“CSV 宏平均”先算每个 CSV 的指标，再等权平均。它们回答的问题不同。默认参数 MIT 的十次 MAPE 分别为 0.689402% 和 0.792423%，不能混用，也不能挑更接近论文的一个就宣称精确复现。两种口径均以实测 SOH 为分母。

## 为什么 RMSE 有时是 0.009，有时是 0.9？

SOH 可以写作 0—1 小数，也可以写作百分数。RMSE 为 0.009 SOH 时，乘 100 后是 **0.9 个 SOH 百分点**。它与 MAPE 的相对误差百分数不是同一种量。图表和正文均应结合单位阅读。

## 为什么没有只展示最好的一次？

单次结果会受 seed、初始化和训练波动影响。本项目保留十次均值、样本 SD 及逐次记录。固定 repeat1 的曲线只是预先选定的展示，不能代替十次统计。比如 MIT 默认参数 repeat1 的 pooled MAPE 为 0.635553%，但十次均值为 0.689402%。

## CPU 复载通过，意味着预测逐位一样吗？

不意味着。20/20 在固定 `atol=1e-6、rtol=1e-5` 下数值一致，prediction 逐位相同为 0/20；最大差为 2.384185791015625e-7 SOH。CPU 与原 GPU 软件环境不同，这一检查验证保存模型能重新得到容差内一致的输出，不替代 GPU 的完整逐位复载证据。

## 代码能跑通，为什么结果仍与论文不同？

公开代码版本、损失公式、参数和历史发表实验并非全部唯一绑定；seed、软件栈、预处理和指标聚合也会影响结果。本项目分别保留版本和对照，已经确认的原因写证据，尚未确认的原因保留为未知。不能把所有差异都归因于服务器或某一个 seed。

## 额外搜索有没有证明 PINN 更好？

192 次替代搜索展示了明确网格和独立整电池验证下的选型结果。它只覆盖 XJTU/2C、3 个固定 seed 和一个固定划分，选中 β=0，也没有与相同结构及搜索预算的 MLP/CNN 作公平胜负比较。因此不能据此宣称单调项有效或全面优于基线。

## 哪些代码是作者的，哪些是本项目补充的？

作者提供了 PINN 模型、数据加载、MLP/CNN 及迁移结构。本项目补充实验批次调度、配置和来源记录、兼容处理、结果收集、独立指标重算、图表和验证工具。两个 slope 的特征导出采用明确标注的替代定义；替代搜索也是新设计协议。论文原作和作者仓库应始终单独引用，新增工具不能冒充作者历史实现。

## 只看结果需要重新训练吗？

不需要。先读[实验结果](实验结果.md)，再打开相关 CSV、图表和独立复核报告即可。重训练应先核对代码版本、数据来源、配置、损失通道和输出目录，用单次短任务确认环境后，再决定实验预算。作者入口可能一次启动多次训练，不能把整个批次当作一次运行。

## 仓库是否包含论文原始数据和所有大文件？

以仓库文件和发布附件索引为准。报告中可能保留本地恢复路径、云端路径或未随仓库上传的大文件引用；它们用于记录来源，不意味着这些文件已经存在于 GitHub。原论文及各数据集的下载和使用条件仍遵循原来源要求。

## 怎样判断某个结论有证据？

先查看[21 项结论表](../outputs/full_reproduction/final_results_2120/independent_review_complete/claim_decisions_21.csv)和[25 项图表映射](../outputs/full_reproduction/final_results_2120/independent_review_complete/figure_table_evidence_map_25.csv)，再沿对应报告找到数据范围、损失、指标和来源。训练完成、文件校验通过、与论文数值一致、支持某个广泛主张，是不同层级的判断。
